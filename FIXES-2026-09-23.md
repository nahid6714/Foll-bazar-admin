# Fol Bazar Admin — Fixes applied (2026-09-23)

## Product image update
- Fixed the Android image uploader so it no longer depends on only `/api/upload`.
- Upload now tries the Laravel `/upload` route first and automatically falls back to the bundled PHP/MySQL-compatible `/api/admin.php?action=upload` endpoint when the route is unavailable (404/405).
- Upload response parsing now accepts both Laravel `{ok:true,data:{url:...}}` and legacy `{ok:true,url:...}` formats.
- Added longer upload/network timeouts for larger product images.
- The multipart filename now keeps the correct image extension.
- Product gallery parsing now accepts both a JSON array and a JSON-encoded string.
- Product main image and gallery continue to be saved together when a product is edited.

## Admin API reliability
- Added 404/405 compatibility fallback from the newer Laravel admin REST endpoints to the bundled `admin-data` compatibility endpoint.
- Added legacy `admin.php?resource=...` GET fallback so older cPanel deployments can still load admin data.
- Product variants, order items, complaints and wishlist data now use the bundled compatibility endpoint instead of returning an empty wishlist result or depending on a product-detail response shape.
- Fixed site-setting lookup filtering (`key` vs `setting_key`).
- Fixed site-setting updates to use the Laravel `PUT /admin/settings` contract.
- Normalized site-setting values to strings before saving, matching the MySQL/Laravel text storage contract.
- Product/category updates now include the existing slug, avoiding validation failures on APIs that require it.
- Added longer API timeouts for admin operations.
- Added legacy login fallback and normalized the legacy login response into the same `{data:{user,...}}` shape used by the current app.
